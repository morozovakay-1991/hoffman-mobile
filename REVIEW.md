# Review instructions

## Контекст проекта

hoffman-mobile — кроссплатформенное приложение (Flutter, iOS/Android) для
выпускников Процесса Хоффмана. Backend — hoffman-backend (Laravel). Три уровня
доступа к контенту (без подписки / подписка без подтверждённого статуса
выпускника / подтверждённый выпускник), офлайн-прослушивание медитаций,
дневник 100 дней с последовательной логикой прохождения.

## Что считать Important (🔴)

- Экран или контент доступен пользователю не того уровня доступа, чем должен
  быть (см. раздел 4.1 ТЗ) — например показан незалоченный контент без
  подписки, или дневник доступен без подтверждённого статуса выпускника.
- Токены авторизации или другие секреты хранятся не в secure storage
  (например в обычных SharedPreferences/plain файле вместо
  flutter_secure_storage/keychain).
- Утечка чужих данных на устройстве — например кэш профиля/дневника одного
  пользователя виден после логина другим пользователем на том же устройстве.
- Нарушение последовательной логики дневника: доступ к дню без прохождения
  предыдущего, возможность пройти два дня в одни календарные сутки,
  редактирование уже сохранённого (прошедшего) дня.
- Утечки памяти и не освобождённые ресурсы в аудиоплеере (особенно при
  фоновом воспроизведении) — зависания, краши при длительном использовании.
- Необработанные состояния сети (нет интернета, таймаут, истёкшая сессия) —
  падение приложения или бесконечный лоадер вместо понятного сообщения
  (раздел 11.7 ТЗ).
- Диплинк из пуш-уведомления ведёт на экран без проверки доступа/данных
  (например открывает конкретный день дневника без проверки, что он вообще
  открыт пользователю).

Всё остальное — стиль, именование, структура виджетов — не выше 🟡 Nit.

## Не проверять — уже покрыто CI

- `dart format`, `flutter analyze`.
- Сам факт "тесты прошли" — проверяй, покрывает ли новый тест реальный
  сценарий (в т.ч. граничный из раздела 11 ТЗ), а не просто вызывает метод.

## Лимит на нити

Не больше 5 🟡 Nit в одном ревью, остальное — одной строкой в сводке.

## Обязательно проверять

- Новые экраны используют общий слой сети (core/network — DioClient,
  interceptors), а не разовые прямые HTTP-запросы.
- Виджеты с подписками/стримами (особенно плеер) корректно освобождают
  ресурсы в dispose().
- Новый экран/виджет корректно ведёт себя офлайн — не крашится, показывает
  осмысленное состояние вместо пустого экрана.
- Изменения в логике дневника — вокруг границ календарных суток и часовых
  поясов, а не только "счастливый путь".

## Сводка

Начинай сводку ревью с краткого итога вида "2 критичных, 3 nit" и веди с
"критичных проблем нет", если находок уровня Important нет.
